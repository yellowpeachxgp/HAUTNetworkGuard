## Issue #7：Windows 文字被拦腰裁切

- 链接：<https://github.com/yellowpeachxgp/HAUTNetworkGuard/issues/7>
- 反馈版本：v1.3.20；环境 Windows 11 + 微软雅黑。
- 复核结论：成立。`Windows/src/mainwindow.cpp` 使用 `setFixedSize(460, 640)`，而当前
  UI 在 Qt 6.6 + 微软雅黑下的内容高度明显超过 640px；布局会把 QLabel 压到不足一行。
- 本地验证：在 macOS Qt 6.11.1 的 offscreen 回放中把应用字体放大到 17pt，复现了标签
  高度小于 `fontMetrics().height()` 的压缩现象；修复后窗口高度按内容增长，内容超过屏幕时
  由滚动区域承接。
- 采纳并加固：
  - 宽度固定 460，高度按字体度量和布局内容自适应；
  - 每个 QLabel 至少保留一行文字高度，自动换行标签按当前宽度计算 `heightForWidth`；
  - 内容超出可用屏幕高度时使用 `QScrollArea`，不再压缩标签；
  - 新增 `Windows/tests/layout_tests.cpp`，在放大字体、切换选项后断言所有标签高度。
- 未采纳原补丁中“只在两个文本刷新点重算高度”的窄修法：初次布局、系统字体变化和
  小屏幕场景仍可能裁切；改为统一的 `refitWindowHeight()` + 滚动容器。

## Issue #5 / PR #6：通用 Linux（Debian / Ubuntu）

- Issue：<https://github.com/yellowpeachxgp/HAUTNetworkGuard/issues/5>
- PR：<https://github.com/yellowpeachxgp/HAUTNetworkGuard/pull/6>
- 作者：miku3928；提交：`478b42d`、`119095e`。
- 复核结论：方向成立。OpenWrt 的 `api.lua` / `crypto.lua` / `protocol.lua` 确实与平台解耦，
  配置读取和服务管理是主要耦合点。
- 采纳：
  - 新增共享 `config.lua`，OpenWrt 继续优先 UCI，通用 Linux 回退
    `/etc/haut-network-guard.conf`；
  - `log.lua` 改用共享配置，并在 `print` 后 `io.stdout:flush()`，适配 systemd 块缓冲；
  - 新增 `linux-generic/` 的 systemd 服务、配置模板、安装/在线安装/卸载脚本；
  - 安装、升级和回滚清单纳入 `config.lua`。
- 未直接照搬、已加固的部分：
  - 后端探测改为“存在 OpenWrt 配置或发行版标记才探测 uci”，避免通用 Linux 误用 UCI；
  - 配置解析补齐 BOM、CRLF、整行/行内注释、单双引号、重复键、非法行和空值边界；
  - 安装脚本改为 staging + 原子切换，服务停止/启用/启动失败会回滚；
  - 在线安装固定版本时校验 `SHA256SUMS` 和 tag/版本一致性；
  - systemd 单元增加 `NoNewPrivileges`、`PrivateTmp`、`ProtectHome`、`ProtectSystem=full`；
  - 新增 15 项 Linux 安装/重装/卸载故障注入测试（Lua 5.1/5.3 各跑一遍）；
  - Release 增加 `HAUTNetworkGuard-Linux.tar.gz`，并纳入 `SHA256SUMS`。

## Issue #1：系统托盘

- 链接：<https://github.com/yellowpeachxgp/HAUTNetworkGuard/issues/1>
- 复核结论：当前 Windows 关闭窗口隐藏到托盘的主链路已存在；但托盘不可用或未成功显示时，
  关闭窗口会把应用隐藏到无法找回的状态。
- 本轮加固：
  - `TrayIcon::isAvailable()` 检查系统托盘与图标可见性；
  - 托盘不可用时关闭窗口直接退出，`--startup` 回退为显示主窗口；
  - 托盘状态徽标按 devicePixelRatio 绘制，避免高 DPI 下偏移/模糊。
- 仍需：真实 Windows 通知区域显示和 Explorer 重启场景的人工验收，未在本机冒充通过。
