# HAUTNetworkGuard 状态机契约

日期：2026-09-08

适用范围：macOS、Windows、OpenWrt。桌面端由控制器串行驱动；OpenWrt 由同步的 `session.lua` 驱动，没有手动注销按钮，因此“手动离线保持”只适用于桌面端。

本契约描述学生能观察到的运行状态和自动登录边界。三端可以使用不同的 UI 实现，但同一事件必须遵循相同的状态语义。

## 1. 状态

| 状态 | 含义 | 用户操作 |
|---|---|---|
| `unknown` | 应用刚启动，尚未取得一次有效状态 | 允许检测，不触发重复登录 |
| `checking` | 正在请求状态接口 | 禁止并发检测、登录、注销 |
| `offline` | 状态接口明确返回未在线 | 按自动登录开关和冷却时间决定是否登录 |
| `logging_in` | 登录请求进行中 | 禁止再次登录、注销和自动登录 |
| `online` | 已取得有效账号或 IP 信息 | 允许注销，清除自动登录重试计时 |
| `logging_out` | 注销请求进行中 | 禁止再次登录、注销和自动登录 |
| `error` | 请求失败或响应无法解析 | 显示可理解错误，不能仅凭异常响应触发登录 |

## 2. 事件转移

| 当前状态 | 事件 | 下一状态 | 自动登录 |
|---|---|---|---|
| `unknown` | 启动检测 | `checking` | 否 |
| `checking` | 有效在线响应 | `online` | 否 |
| `checking` | 明确离线响应 | `offline` | 是，受开关/冷却约束 |
| `checking` | 网络错误或异常响应 | `error` | 否 |
| `offline` | 自动登录开始 | `logging_in` | 否 |
| `offline` | 手动登录开始 | `logging_in` | 否 |
| `logging_in` | 成功或已在线 | `unknown`，随后检测确认 | 否，认证应答不能代替在线证据 |
| `logging_in` | 失败或超时 | `error`，可重新检测 | 否；新离线结果也必须等待冷却 |
| `online` | 手动注销开始 | `logging_out` | 否，并进入手动离线保持 |
| `logging_out` | 注销成功或当前不在线 | `offline` | 否，保持手动离线 |
| `logging_out` | 注销失败 | `unknown` 或重新检测 | 否；保留用户暂停自动重连的意图，可再次注销 |
| 任意非忙状态 | 网络变化/定时器 | `checking` | 由检测结果决定 |

## 3. 必须保持的边界

1. `error` 不等于 `offline`。状态接口超时、非法 CSV 或解析异常不得直接触发自动登录。**兼容边界尚待收口：现有三端协议解析器把 HTTP 成功后的空正文归为离线；本轮没有改变这项历史语义，不能声称所有空响应都已被阻止。** 需在 M1 中用校园网响应证据决定是否保留。
2. 同一时刻状态检测、登录、注销合计最多一个请求；忙碌时重复点击和定时器均不发请求。完成回调必须同时匹配请求编号和操作类型，旧回调不能改变当前状态。
3. 手动和自动登录失败都进入冷却。基础间隔为 `max(60 秒, 检测间隔)`，从完成回调起算；连续失败按基础间隔的 1、2、4 倍递增，常规配置最多 300 秒。配置间隔若大于 300 秒，不缩短该间隔。采用单调时钟，冷却期间仍可手动纠正凭据并登录。
4. 用户主动注销后暂停自动重连，包括服务端返回当前未在线、注销失败，以及后续探测再次在线的情况。只有用户明确点击登录才恢复；修改自动登录开关、定时探测和网络变化均不撤销暂停。暂停保留在当前进程内，重启后从 `unknown` 重新探测。
5. 进入 `online` 后清除自动登录冷却；再次掉线时允许重新触发登录。
6. 缺少凭据时保持离线或错误提示，不得提交空凭据请求。
7. 所有转移都要记录原因、动作、分类和耗时；日志账号必须脱敏。

## 5. 现场验收场景

- 启动时无网络：进入 `error`，网络恢复后下一轮进入 `checking`。
- 明确离线：只发起一次登录；登录未完成前的定时器和重复点击都被忽略。
- 登录失败：显示失败原因，等待冷却后才允许重试。
- 手动注销：注销成功后不被下一轮检测立即自动登录。
- 状态接口异常：保留上一次在线判断或进入错误展示，不把异常响应当作离线。
- 在线后掉线：先记录 `online -> offline`，再按冷却规则触发重连。
- 重启自启：只产生一个进程，状态机从 `unknown` 开始，不继承过期的忙碌状态；Windows `QLockFile` 与 macOS bundle 实例检查已加入构建和锁竞争验证。
